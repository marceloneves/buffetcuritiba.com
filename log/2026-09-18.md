## Otimização de Core Web Vitals / Lighthouse (43 páginas)

Linha de base (Lighthouse 12, mobile, servidor local com gzip): home com
Desempenho 76 (FCP 3,2 s, LCP 4,3 s), páginas de serviço ~87.

### Alterado
- CSS inline: cada página carregava ~460 KB de CSS (Bootstrap, Font
  Awesome, Boxicons, Flaticon, animate.css, tema e estilos do WordPress).
  O CSS de cada página foi passado por PurgeCSS contra o próprio HTML e os
  scripts que adicionam classes (`main.js`, `jquery.meanmenu.js`,
  `cta-modal.js`), minificado e reunido num único `<style>` — ~40 KB por
  página. HTML de ~540 KB para ~105 KB (home: 572 KB → 142 KB).
- Google Fonts: os 4 `@import` (Rubik, Roboto, Barlow Condensed,
  Montserrat), que bloqueavam a renderização, foram removidos. Barlow e
  Montserrat não eram usadas. Rubik e Roboto agora são servidas do
  próprio site (`assets/fonts/`), em fonte variável WOFF2 com só os
  caracteres usados no site e só os pesos usados (Roboto 400–700: 43 KB →
  21 KB; Rubik 400–500: 35 KB → ~20 KB), `font-display: swap` e fontes de
  fallback com métricas ajustadas (sem deslocamento de layout na troca).
  Preload apenas da Roboto (fonte do corpo).
- Fontes de ícones (Font Awesome, Flaticon, Boxicons): substituídas por
  subconjuntos só com os glifos usados (~3 KB no total, antes 165 KB com
  preload). As `@font-face` duplicadas que apontavam para
  `https://buffetcuritiba.com/fonts/...` (404 + erro de CORS no console)
  foram removidas.
- Banner da home e topo das páginas internas: a imagem
  `buffet-curitiba-scaled.jpg` era só um degradê horizontal
  (#ff5757 → #8c52ff). Trocada por um SVG inline com o mesmo tamanho
  intrínseco (2560×600), mantendo o mesmo recorte do `background-size`;
  o elemento LCP não depende mais de nenhuma requisição.
- Imagem principal das páginas de serviço (visível sem rolar no celular):
  sem `loading="lazy"`, com `fetchpriority="high"` e recomprimida a partir
  do original (`*-670w.webp`, ~40% menor). Na página Serviços, o primeiro
  card também é carregado com prioridade alta.
- Cards de serviço: nova variante `*-540x360.webp` no `srcset` (tamanho
  exato para 307 px de largura em telas de densidade 1,75); antes o
  navegador baixava a de 768 px.
- Imagens dos cards e imagem principal das páginas de serviço agora
  dentro de `<picture>` com fonte AVIF (`*-392x262.avif`,
  `*-540x360.avif`, `*-768x512.avif`, `*-670w.avif`; ~33% menores que o
  WebP, sem diferença visível). O `<img>` WebP continua como fallback.
- `.htaccess`: tipo MIME e cache de 1 ano para `.avif`.
- E-mails protegidos pelo Cloudflare decodificados para `mailto:` direto;
  o script bloqueante `email-decode.min.js` saiu das páginas (se a
  ofuscação de e-mail do Cloudflare estiver ativa, ele reaplica sozinho).
- Beacon do Cloudflare Web Analytics passou a ser carregado pelo loader
  adiado já existente (SuperLazyLoad), como os demais scripts.
- Removidos `preconnect` inúteis (`index.html`, doubleclick, google,
  google-analytics).

### Corrigido
